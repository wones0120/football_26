# Saved Analyst candidates in Learning

Learning reads the original `strategy_runtime.football_analyst.candidates` array in addition to legacy candidate contracts. `player_master_id` and `role` become canonical roster/Captain signatures for evaluation; no raw-name join or new lineup generation occurs. Each source variant retains its recorded candidate ID if any, source array ordinal/hash, scenario IDs and conditional world scores. Array position is not claimed to be generation order or selector rank. Canonical roster counts remain separate from source variant counts; changing Captain identity creates a different Showdown roster.

Baseline mean, individual-P90 sum and salary are summed from the **saved input snapshot's player moments**, applying Captain1.5 once. Missing snapshot moments stay unknown. Conditional scenario scores are preserved separately, never relabelled as unconditional mean, joint P90 or the recorded selector objective. Unknown original selector ranks/objectives stay unknown.

Canonical roster correspondence includes ambiguous candidate origins as separate `entry_correspondence` runs. This permits inspection of all relevant stored runs without selecting a newest run or inventing assignment/submission timing. Correspondence is not proof of origin or submission. It is excluded from entry-linked historical promotion aggregates.

Stored creation/cutoff/kickoff timestamps are useful timing evidence but do not prove original source availability or executable original code. The Analyst adapter labels those evaluations retrospective and chronology unverified until independent original-code/source proof is available. Existing historical source facts and manifests are not edited. New reader results create new builder-versioned slate/weekly reports; opening older saved reports never rebuilds them.

The reader loads only candidate arrays and the compact frozen player fields needed for baseline metrics rather than expanding full raw player context for every saved run. Focused fixtures cover legacy/new Classic/Showdown, canonical identity, Captain variants, duplicates, missing actuals/moments, contaminated or malformed source rows, hashes, ambiguous correspondence and timing-versus-proof. Real acceptance rebuilds through Learning → Build Week Learning Report → Open saved report and verifies the preexisting report remains byte-identical.
