# Authored Analyst refresh and consumption

The [Monday public acceptance](../../research/analyst_research_closure_20261019/acceptance/REVIEW.md) now verifies an actual authored sourced no-change publication, matching fresh Prepare closure, saved optimizer run, readable reopened research and native CSV responses. This is operational producer/consumer evidence; it does not establish an always-running autonomous researcher, numerical forecast improvement or activation of the new shared-world selector. Final roster dressing and current upload clearance remain separate.

Preparation distinguishes source compatibility from authored football research. A checked neutral packet is `reference_only`; a partially supported authored packet is `mechanisms_partial`; a sourced material or explicit no-change assessment with matching dependencies is `mechanisms_current`; a changed dependency is `refresh_pending`. These states are separate from data readiness, final inactives and native CSV eligibility. Neither current coverage nor a conditional scenario asserts calibrated occurrence probability.

`analyst_preparation.prepare_handoff` freezes per-game semantic role/designation/count/market dependencies from canonical context and preserved original provenance. Changed meaningful facts create bounded immutable research requests. Equivalent role/roster recapture, resolver execution clocks and duplicate retained facts do not renew prose or invalidate unaffected games. Original publication/effective facts, practice sequence, changed roles/counts/gap periods and unknown-versus-zero remain significant. Native DraftKings `Game Info` is preserved separately from its canonical schedule binding.

The application creates requests; it does not independently author football research inside the solver. An existing authorized research worker must investigate only affected games and publish through the normal typed packet import. The code does not install or claim execution of a new scheduler, model API or paid dependency.

## Producer path

1. Use normal public **Prepare slate for optimization** with the intended scope/settings. Inspect `analyst_handoff.research_requests` and `research_dependency_snapshot`; source readiness and lock must still pass.
2. Load the immutable request with `analyst_research_requests.load_request(request_id)`. Default ledgers are `artifacts/analyst_research_requests/{requests,publications,closures}`. Preserve original facts and source clocks; investigate the exact canonical scope. Do not invent a replacement recipient, target transfer or scenario likelihood.
3. Author a normal typed packet and call `publish_research(requests, authored_packet, assessments=..., producer=..., completed_at=...)`. Each requested game needs sourced `material`, `no_change` or `partial` disposition, mechanism, counterevidence, unknowns and verified packet source IDs. Material output also needs a nonneutral same-game typed scenario with nonzero elasticity. Source evidence must have been available by its actual authorship clock. Explicit no-change uses no material scenario IDs and retains its sourced rationale. Publication alone is `published_prepare_pending`.
4. Run fresh public Prepare that actually selects the new published packet. Call `finish_preparation(publication, handoff, handoff['research_dependency_snapshot'])` on that exact immutable handoff. The function verifies actual publication/checked packet bytes, compatibility, current surviving mechanisms, source/dependency scope and fresh clocks before writing append-only closure. Partial/stale coverage cannot claim a closed current producer loop.
5. Closure does not mutate the already frozen handoff. A later public Prepare with the same packet/dependencies discovers and exposes `producer_loop_closed` and its closure receipt. Use that later preparation if the saved run must show closed status. Then use public **Run Optimizer → reopen saved results → native CSV validation**. Otherwise retain the closure artifact separately and state that the saved handoff predates it.

Source changes between publication and fresh preparation require revalidation/research of dependent games. Equivalent recapture is idempotent; it cannot renew the original request/authorship clock. A changed slate or user preference does not alter football facts or transfer excluded opportunities. The standard objective/defaults and existing count/control behavior remain preserved.

## Saved result evidence

The normal handoff binds coverage/request lineage into saved optimizer parameters. The merged scenario report retains actual surviving material scenario IDs, publication/request/dependency references and a full-roster explanation: canonical players/roles, salary, base expected score, shared assumptions and captured legal-model alternative. A report branch that did not capture an alternative says so explicitly. Conditional effects are assessed through the existing scenario machinery; this metadata adds no objective bonus or baseline projection mutation. Captain changes score/salary at the roster slot, not physical opportunities.

The prepared Analyst summary, saved Analyst section and readable HTML report render this evidence directly: authored/no-change status, mechanism, supporting source IDs, counterevidence, unknowns, consumed conditional inputs and exact closure reference. Construction status remains separate and visible. A material input receipt does not itself prove that the selected roster changed. Reports for modes that do not use Analyst research omit the unrelated research section.

Tests exercise exact native/canonical identity, real composed-context and count-role/gap recapture, changed source/role/practice/count facts, future clocks, immutable receipts, false material claims, partial-closure rejection, later closure discovery and a six-player material-world consumer saved/reopened in an isolated fixture. These mechanical checks do not establish that current-slate research was authored, that an autonomous worker is installed, or that public/browser/CSV acceptance ran. Operational execution requires its own current receipt.
