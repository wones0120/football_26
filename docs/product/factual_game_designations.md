# Factual game designation evidence

Classic/Showdown canonical context carries `factual_game_designation_v1`. It records effective game designation, selected fact, original facts, superseded evidence, unresolved conflicts and evaluation time. Raw salary/injury flags remain immutable. User Q exclusions and explicit Assume Q Out evaluate the same resolved designation; they do not establish football availability themselves.

`NO_GAME_DESIGNATION` is an affirmative typed final-report fact, separate from game dressing, roster membership, practice participation and healthy/full workload. A generic empty provider cell or roster ACT cannot clear a native Q. New definitive adverse reports supersede an older final report; a current contradictory Q stays unresolved. Publication/modification clocks remain distinct from current HTTP observation and capture.

## Bounded official source intake

`POST /api/pregame-context/official-final-report?season=…&week=…&slate=…&team=…&source_uri=…` verifies one supplied official club report. It does not crawl, modify user preferences, run projections or generate lineups. It checks the club HTTPS host against the shared registry, unique native slate matchup/kickoff, explicit article week/opponent, original NewsArticle publication/modification, current HTTP observation, and a complete final-practice-day game-status table. Unsupported/missing structures abstain. Individual identity resolution requires native aliases or canonical team + position + normalized name; raw names alone never join records.

The original HTTP body/headers, parser contract and clocks are captured through existing immutable source storage. Canonical context is appended through the existing context service. A Saturday final report can be verified Monday without rewriting its Saturday publication. Later contradictory evidence is not discarded. The parser intentionally does not reinterpret blank generic weekly NFL report cells as final clearance.

The next normal **Prepare slate for optimization** consumes this context alongside current official, native, roster and depth sources. A new source changes the preparation binding. **Run Optimizer → reopen saved results → Check upload readiness** remain required operational checks. A source import alone is not a lineup refresh or entry clearance. No browser downloads or contest submission are needed for API CSV validation.

## Scope and limits

The shared consumers in this change are Classic/Showdown composition, Q preference eligibility, both explicit automatic-Q availability paths and saved upload/readiness. Existing untyped historical packets keep their prior fallback behavior; no original artifact is rewritten. Tiers and Single Stat retain their separate native-pool status contracts; this release does not claim their import/status behavior changed.

This factual repair does not invent replacement targets, redistribute excluded players’ opportunities, change base projections/Captain workload rules, restrict kickers or promote a new selector. A reference-only Analyst packet still lacks authored mechanisms; an effective factual designation is not a completed football research producer loop.
