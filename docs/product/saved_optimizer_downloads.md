# Saved optimizer DraftKings downloads

In **Operations → Run activity → Recent optimizer runs**, each saved run has **Download Recommended** and **Download All**. Files belong to the clicked row, even when a different run is open in the results panel. Feedback and errors stay beside that row; changing slate clears stale feedback.

**Download Recommended** exports exactly the run's persisted GPP recommendation. The existing contract ranks valid saved candidates by unconditioned projected points, then marginal upside and canonical identity. It is provisional, not calibrated paid-finish EV. The server checks saved run/scope/projection lineage and the recommended candidate's canonical identity. Missing or invalid recommendations are unavailable; the UI does not invent a first-lineup fallback.

**Download All** exports every saved selected lineup from the completed run, excluding unsaved internal candidates. A completed underfill includes its actual saved count; queued/running/failed runs cannot download. More than 500 saved lineups produces a deterministic ZIP of CSVs, each with at most 500 rows.

The existing server exporter verifies canonical player identity, numeric native DraftKings IDs, roster shape, salary cap and duplicate-player/lineup rules. Classic headers are `QB,RB,RB,WR,WR,WR,TE,FLEX,DST`. Showdown headers are `CPT,FLEX,FLEX,FLEX,FLEX,FLEX`, with the saved Captain-specific DraftKings ID in CPT and base site IDs in FLEX. No entry template is needed for DraftKings → Lineups → Upload Lineups; updating assigned contest entries remains a separate workflow.

Explicit preliminary reports remain blocked. A saved `entry_readiness.entry_ready=false` still blocks Classic. For completed single-game Showdown runs with authenticated prepared model inputs, **Check upload readiness** captures a genuine current NFL weekly report and appends a separate `saved_showdown_upload_clearance_v1` evaluation record. It validates exact saved rosters/projection/game scope, current canonical availability and unchanged roles, native CPT/FLEX IDs and salaries against latest completed local DraftKings ingests, immutable consumed salary-file hashes, and pre-lock timing. An explicit named questionable exception also needs an official full-practice/no-designation match by canonical ID. Unknown, OUT, Q/D, stale evidence, changed roles/native IDs/salaries, or unresolved identity blocks the check. Official evidence must be at most six hours old, canonical role/availability at most 24 hours; future clocks are rejected.

A successful check is **UPLOAD_READY_PENDING_INACTIVES**, valid for 30 minutes or until lock, whichever comes first. It deliberately keeps `entry_ready=false` and `final_active_confirmed=false`; final official inactive reconciliation, live native draft-group publication and actual site acceptance remain unverified. The historical research decision is never rewritten. Every download rechecks authenticated current evidence, expiry and semantic input binding; changed native/status/role evidence invalidates the receipt. Equivalent source recaptures do not alter the semantic binding. The UI shows the pending-inactives limitation and requires another check after reload or expiry. It cannot create a clearance from client-supplied status. No projection, constraint, candidate selection or recommended lineup changes.

Use `POST /api/optimizer/results/{id}/draftkings/readiness` for this check. Export receipts link its append-only record ID. `GET .../draftkings/download` revalidates on the server; no client flag bypasses it. Legacy runs without a stored clearance decision retain existing server validation policies.

Successful downloads reuse append-only export receipts linking the run, exact content hash/bytes and all matching saved lineup IDs. Ambiguous canonical matches remain explicit, rather than selecting a presumed origin. Repeated equivalent files have stable bytes/receipt identities. Downloads do not establish assignment, submission intent or confirmed entry, and never open or upload to DraftKings.
