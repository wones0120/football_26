# Saved week learning reports

The Learning → Review section lists the latest original report for each season/week, scoped to the entered DraftKings username. Show previous versions reveals earlier snapshots. Open saved report loads the exact stored JSON into the existing report review and switches only the independent Learning review season/week. Download original JSON preserves saved bytes; the existing ChatGPT Markdown download remains available after opening.

Reloading the app repopulates the library from the server; no report rebuild, source refresh or financial import occurs. A report's original generated time, partial/completed status, evidence hash, and missing evidence remain unchanged. Recovered originals are labeled separately from newly generated reports. Earlier versions remain accessible and are never replaced by reconstructed reports.

Successful future `SlateLearningService.generate_week` calls save their aggregate report before returning. The content-addressed ledger is `artifacts/weekly_learning_reports/<SHA256>.json`, with a separate immutable `.receipt.json` containing scope, original generation time, receipt time and recovery provenance. It uses the repository's existing filesystem artifact pattern; no database schema change is required. Preserve this directory in application backups. Per-slate database reports remain separate original evidence.

Read-only endpoints under `/api/learning/weekly-library` list by `entry_user`, optional `season`/`week`, and `latest_per_week`; `/<sha>?entry_user=...` reopens; `/<sha>/download?entry_user=...` downloads exact bytes. Payload hashes, report/receipt scope and username are checked. Missing or corrupt originals are unavailable rather than rebuilt. This local app's username filter is scope selection, not an authentication system.
