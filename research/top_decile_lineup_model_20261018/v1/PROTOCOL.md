# Complete-lineup top-decile model prototype, predeclared

User requested a model learned from top10% complete lineups in each slate, compared with the rest of the field. This is a separate bounded research prototype; no live projections, settings, entered runs or selector defaults change. Weeks1–6 outcomes were previously inspected; temporal holdouts here are retrospective and not fresh blind validation.

For each full final contest field, use valid distinct EntryId and observed final Points to find the score at ceil(0.10*N). Every tie at that score is positive; the positive fraction may exceed10%. Missing roster rows remain in the label denominator when their final points/entry are valid, but cannot train until canonically resolved. Do not pool ranks from different contests. Format and native pool/slate scope must be verified; Tiers/SingleStat remain separate inventory only.

Resolve entry roster tokens using source-file/contest/pool/format-slot-specific canonical observations and their native salary provenance, never raw name alone. Canonical signature treats Classic FLEX ordering as interchangeable and Showdown Captain identity as distinct. Deduplicate identical canonical rosters across entries/contests for training, retain entry multiplicity, all contest-specific labels and contradictory field labels. Equal-weight per-contest soft target for a deduplicated roster is implemented as equivalent fractional Bernoulli loss; it is not a fabricated unique source label. Evaluate contest-specific labels separately.

Historical predictors: latest physically stored completed same-slate projection snapshot before the first contest kickoff, with model creation and source-feature creation/cutoffs prelock. No fallback to postgame/current projections. Missing projected player moments make a roster unscoreable, never imputed projections. Canonical salary/team/position evidence must predate lock. Optional role/game context must have usable original pregame feature clocks. Actual scores, ranks, player outcomes, final ownership, payouts, and eventual entry multiplicity are labels/audits only and never predictors.

Core features: summed baseline mean, marginal spread summary explicitly not jointP90, within-roster mean concentration/minimum, salary cost and variation, actual game/team opportunity dependencies and QB/receiver relationship counts as features (no forced stack rule). Rich features, if evidence coverage permits: recorded pregame workload/share concentration, role, team implied points/total/spread and verified original ownership only. Missing optional context stays explicit; no fake healthy or zero workload. Scaler/transforms fit training only.

Separate Classic and Showdown regularized logistic prototypes (C=0.1, no hyperparameter search), with projected-mean rank baseline. Rolling temporal evaluation: trainW1–3/testW4, trainW1–4/testW5, trainW1–5/testW6. Entire weeks and their overlapping games/slates stay together. Count independent slates/games, not entries as independent evidence. Report small-sample limitations; no performance promotion based on one heldout slate. No winner-tuned feature or coefficient selection.

Metrics: ROC-AUC/AP/Brier and calibration where adequate; top-decile hit rate at fixed5rosters per heldout contest, versus projected-mean ranking on the exact same complete-feature canonical roster cohort. Retain full-field missingness/coverage and canonical duplicates. Rank contest fields for descriptive evaluation only: external-field lineups are not represented as legally generated candidates under user's settings. A separate saved38-roster pool comparison must enforce unchanged original hard controls and report candidate top-decile coverage upper bound; cannot select missing candidates. No cash/win probability or ROI claim without appropriate field/financial evidence.

Artifacts: versioned data manifest, source hashes/chronology, deterministic split IDs, feature definitions, coefficients/model, per-contest metrics, independent-group counts and report accessible from existing app report catalog. Training is one bounded job, no broad sweep or new dependencies.
