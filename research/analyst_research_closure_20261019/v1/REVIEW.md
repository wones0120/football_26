## Implemented path

`analyst_preparation.prepare_handoff` now freezes a separate canonical, per-game semantic dependency snapshot from the full supplied context, source manifest and optional frozen count receipt. Semantic role/designation/count/market changes create bounded immutable requests. Pure recapture clocks, execution IDs and whole-slate file checksum changes remain original provenance; they do not renew authored prose or invalidate unaffected games. Original publication/effective values, conditions, count/period/gap facts and meaningful source content remain dependencies. Missing values remain null. Supplied contradictory game/period identity and future role/source clocks are rejected.

The existing public salary adapter's `game_id` can contain native DraftKings `Game Info`. The request adapter distinguishes that serving key from canonical schedule identity: an explicit canonical ID must agree; otherwise a unique canonical team/opponent/period binding is required, with native team/date validation and original native identity preserved. No display-name join is used.

An existing research worker can load each immutable request, investigate its affected mechanism and call `publish_research`. The function requires a sourced authored assessment of `material`, `no_change` or `partial`; source evidence must be available by the actual research completion clock. Material output must reference a same-game nonneutral typed scenario with nonzero elasticity. A forged derivative flag cannot bypass that original-publication rule. Existing packet validation/import remains the only packet publication path. No numerical football effect, replacement recipient or occurrence probability is generated by the request layer.

A publication is `published_prepare_pending`, not closed. `finish_preparation` requires the exact immutable publication, actual published and checked packet bytes, a fresh valid Prepare compatibility receipt, complete current coverage and matching semantic dependencies. It records an append-only `producer_closed` receipt. Subsequent handoffs with the same authoring packet/dependency expose that receipt. Rechecking source compatibility remains distinct from authoring research; ordinary compatibility metadata still correctly says its machine check did not research football.

`bind_handoff` forwards research coverage and request lineage into the existing saved optimizer parameters. `analyst_scenarios` adds a saved full-roster research explanation and actual material-scenario consumption summary in both existing scenario report branches, without changing scenario scoring or objectives. It records canonical roster roles, salary, base mean sum, shared portfolio assumptions and the existing legal-model reference alternative when captured. The scenario-first path explicitly reports when its existing generation did not capture that alternative; it does not invent one.

## Callable producer contract

1. Fresh public Prepare emits `analyst_handoff.research_requests` and `research_dependency_snapshot`; request files live under `artifacts/analyst_research_requests/requests/<request_id>.json`.
2. `load_request(request_id)` returns its immutable canonical game/dependencies, original source/actor/count provenance, unknowns, prior packet hash and first request clock.
3. The existing Codex research worker investigates primary evidence and authors a normal typed packet. Call:

```python
publication = publish_research(
    requests, authored_packet,
    assessments=[dict(
        game_id=canonical_game_id,
        disposition="material",  # or sourced no_change / honest partial
        mechanism="Authored supported conditional mechanism",
        counterevidence=["Relevant contrary evidence"],
        unknowns=["Occurrence likelihood remains unknown"],
        source_ids=[verified_packet_source_id],
        scenario_ids=[nonneutral_typed_scenario_id],
    )],
    producer=existing_worker_identity,
    completed_at=actual_aware_completion_clock,
)
```

A `no_change` assessment uses an empty `scenario_ids` list and a sourced rationale. It does not claim numerical change. `partial` cannot close complete current coverage. Unaffected authored game assessments retain their original author/clock when another game is revised.

4. Run fresh public Prepare selecting the new normal published packet. Then call `finish_preparation(publication, prepared_handoff, prepared_handoff['research_dependency_snapshot'])`. An intent-specific handoff must actually bind the publication; a generic different packet/hash is not accepted.
5. Use the existing prepared optimizer workflow, reopen saved results and validate its native CSV and visible explanation. Parent owns this operational acceptance and any coordinated process reload. No second service, paid API, secret or agent framework is introduced.
