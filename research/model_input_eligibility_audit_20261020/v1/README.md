# Feature-to-model eligibility audit

The catalog has 244 full feature definitions; this does not imply 244 model inputs. Existing consumers accept a fixed 57-column team schema and a 251-column player schema (194 player + 57 team context). The receipt inventories exact frozen refs, ordered columns, labels, source contracts and all 320 catalog dispositions without changing runtime or fitting.

The smallest controlled model experiment reuses these prior-only matrices as **revised-history** evidence. Existing team splits are 448/544/544 scoreable rows. Corrected player preprocessing separates 4,247 train / 5,109 validation / 5,281 2025 retrospective test / 1,347 inspected 2026 diagnostic rows. The old mixed test receipt remains preserved. Five receiving eight-game numerical fields were entirely missing in training and must stay frozen unknown. A owns the team-side matching guard repair.

Newly approved FTN/PFR and personnel features are not automatically consumed. FTN 2023–25 publication is postseason; original pregame availability is unproved and current 2026 rows are unsupported. A full-season profile must never enter a same-season target. Target-specific lagged versions require a new explicit adapter and an honest retrospective availability policy. Team existing `_pool` means use known samples alongside unknown counters; catalog labels alone do not establish latest exact full-scope denominator equivalence.

Sparse source facts retain their scope: official temperature covers one DEN/LAC 2025 game; original absence and weather contexts are bounded. Unknown availability does not mean active, healthy, starting, or zero production. Pair/lineup/scoring and salary-comparison evidence belongs to a declared dependence or roster consumer, not a blind point-model column append. Diagnostics remain admission/ancestry evidence unless an explicit time-safe predictor contract is reviewed.

This audit reads only small receipts/register and consumer source; it does not re-decode or hash large matrices, replay sources, fit estimators, change settings or approve activation. Exact refs, primary restrictions and next admission gates are in `AUDIT.json`.
