# Original PFR advanced-stat source capture

Feature-only source package `pfr_native_source_v1` captures original Parquet bytes from the public nflverse PFR release used by the installed `nflreadpy.load_pfr_advstats` provider. A release-asset inventory is retained by SHA before downloading. All 40 assets (2,947,446 bytes) were acquired exactly once in a bounded sequential13.88s job: weekly passing/rushing/receiving/defense for2018–2026 plus four all-season aggregate files. No model, optimizer or forecast is run.

The adapter preserves native PFR player and game IDs, raw columns, zeros, nulls, signed values and annual multi-team labels. Weekly native game/team/season/week and one-to-one PFR/native-game crosswalks are validated; postseason source types REG/WC/DIV/CON/SB remain explicit (REG is selected separately, not postseason relabeled). Annual files use the provider's `tm` field, and remain player-season aggregates; they are never copied into each week. The prior-week helper rejects season-grain inputs. It filters REG periods strictly before the target without creating missing participants or a full-game completion claim.

The first conservative validation result remains in the original capture receipt. Subsequent same-byte validation recognized the actual postseason vocabulary and annual team-column spelling; no source was rewritten or fetched again. Final validation finds39 valid native-grain assets, zero schema failures, and one annual defensive file with16 missing native player IDs. These16 source rows were retained and persisted in the existing identity quarantine using immutable content-hash/row keys, with source snapshot links in the separate persistence receipt. Player names are displayed for human review only; no canonical player or alias is guessed, and repeated evidence never reopens a human-resolved record. Canonical PFR-to-UUID mapping for later derived features is a separate required step, not claimed by native-grain validation.

Weekly observed rows total: passing5,610; rushing19,100; receiving37,017; defense64,627. Annual rows total848/2,996/4,476/8,146 respectively. Native weekly rushing data actually contains contact-yard and broken-tackle fields; the annual-versus-weekly limitation is determined field by field from actual schemas, not assumed from dictionary headings. `source_coverage.json` preserves the observed per-grain/year column availability. Numeric field presence alone is not proof of complete or non-null measurement, an exact catalog definition, or a causal effect.

Native frames are captured as remotely downloaded Parquet, not dataframe-to-CSV reconstructions. Actual download/observation/capture clocks, source URL, raw byte SHA, provider release update and HTTP headers remain attached to indexed SourceSnapshots. Provider update/HTTP clocks do not establish original historical pregame publication. Current2026 rows may contain incomplete games; final-game completeness is not established by a stat row. All current outputs are postlock feature inventory and explicitly non-serving/non-reconstructed historical pregame evidence. Annual aggregates carry a hard separate grain to prevent whole-season leakage.

Source-only review requests zero catalog-ID promotions. Definitions, measured feature builders and canonical identity mappings still need their own evidence and review. Existing snapshots, lineups, settings and model artifacts are preserved.

Primary provider documentation: [nflreadr PFR loader](https://nflreadr.nflverse.com/reference/load_pfr_advstats.html) and [PFR passing dictionary](https://nflreadr.nflverse.com/articles/dictionary_pfr_passing.html). The installed provider code confirms weekly per-type/year and season all-history file paths. Missing additional dictionary pages are not treated as proof that the data is unavailable.
