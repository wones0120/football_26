# Official dated practice and full-position final-report features

`official_role_report_features_v1` reuses the existing strict final-report parser before extracting all three authored practice-day columns from the same retained official body. Scope requires official club host/canonical URL, exact season/week/opponent, authored final/game-status marker, publication/modification clocks and pregame original observation. Indexed snapshot bytes and manifest are actually verified; no source is fetched.

Practice calendar dates come from the authored weekday headers within that validated game week. They do not come from HTTP capture time. The final practice date follows the existing final-report contract (day before Thursday games; two days before other games). Header dates must be unique and ordered within six days. Full/Limited/DNP map to FP/LP/DNP; missing/unknown cells remain null, never DNP. The original source observation/receipt/publication clocks remain attached to every dated fact, so a report captured later does not become known on the earlier practice day.

Full-provider-roster identity uses persisted official source keys first, then a unique canonical candidate matching team, normalized position family and normalized name. T/OT and C/G→OL or official CB versus roster DB are explicit position-family equivalences; an unscoped display name never joins. Resolutions preserve source and roster positions. The existing alias/quarantine writer is exposed as a separate caller-transaction operation; derived facts alone do not claim that actions have been persisted.

Actual source output: one retained WAS final report,22 players across all positions,22 official designations and22 dated practice trends; no unresolved official-report identities. Earlier live collector had intentionally retained only offensive player context and the last practice column. This feature extraction recovers the source's full-position rows and three original columns without rewriting the old context or changing availability/optimizer policy. SF final-report bytes are not present in this verified dataset; no SF facts are invented. There are still no sourced workload restrictions or independent full-team roster completeness certification.

All new output is derived after Monday lock and marked descriptive/non-serving. Model, forecast, optimizer and user settings are untouched. The snapshot source remains immutable; new outputs get new content-addressed files.
