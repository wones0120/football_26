# A06.1 — conserved event taxonomy and zone derivation

`opportunity_events.py` derives descriptive official-stat pass/rush/target opportunities from a supplied immutable-source JSON event set. It never reads research/training paths or generates a forecast. Source-native game/play/player keys and canonical UUID mappings remain distinct. Duplicate plays, invalid canonical identity/cardinality and invalid REG season/week scopes reject explicitly. PRE/POST and missing type cannot merge into a REG window.

A sack is a dropback rather than an official pass attempt; source-reported dropback remains its own flag. A spike counts as an official passing attempt; a kneel counts as an official rushing attempt with a separate subtype; scramble and other rush subtypes remain distinct. Two-point tries/no_play do not enter official component counts. A penalty flag alone does not erase an otherwise valid play. No receiver ID is invented from pass completion. Missing receiver attribution on a non-spike pass leaves targets unknown while preserving the pass attempt; a verified spike can establish no target. Missing play type remains unknown rather than silently non-offensive. Unknown required flags remain channel-specific missing coverage, not zero.

Each counted channel partitions into outside20,6–20,inside5,unknown using opponent-goal distance. Goal-to-go is overlapping and separate; it is never a fourth additive zone. Passing and target opportunities share the same native event, not two additive offense budgets. Unmapped/missing actors retain counted team opportunities and return explicit identity-review requests. The pure derivation does not claim these requests were persisted; an eventual ingest hook must use the existing queue transaction.

Partial/unknown team or player channel totals are null, with known counted lower bounds and channel coverage retained. An all-unknown game/team remains visible. Zones partition the known counted events; they are not claimed to be complete denominators when eligibility is incomplete. Optional independently supplied official weekly components produce matched/mismatch/unknown reconciliation without rewriting events; source IDs/import clocks are retained when provided.

The actual count-forecast consumer accepts a supplied versioned checksum-bound event receipt and validates source clocks, declared source verification, prior REG game scope and decision cutoff.
